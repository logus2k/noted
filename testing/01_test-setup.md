# 01 - Environment Setup - Test Procedure

## Goal

Validate that noted and all supporting services launch correctly from Docker Compose, that the web interface loads, and that integrated services (MLflow, Airflow, MinIO) are accessible from within noted.

---

## Prerequisites

- Docker and Docker Compose installed
- Repository cloned and `.env` configured in `services/` (copy from `.env.example`)
- Mount configuration in `data/NOTED.md` (YAML frontmatter with mount names and host paths)
- `data/docker-compose.mounts.yml` exists (auto-generated by noted, or create with `echo "services: {}" > ../data/docker-compose.mounts.yml` for first run)

## Test 1: Docker Compose build and launch

1. Navigate to the `services/` directory
2. Run:
   - With GPU: `docker compose -f docker-compose.yml -f docker-compose.gpu.yml -f ../data/docker-compose.mounts.yml up -d --build`
   - Without GPU: `docker compose -f docker-compose.yml -f ../data/docker-compose.mounts.yml up -d --build`
   - Local (no domain): add `-f docker-compose.local.yml` to the command
   - To rebuild only noted: append `noted` to the command
3. **Expected:** All containers start without errors
4. Run `docker ps` and verify the following containers are running:
   - `noted`
   - `noted-postgres`
   - `noted-redis`
   - `noted-airflow-apiserver`
   - `noted-airflow-scheduler`
   - `noted-airflow-dag-processor`
   - `noted-airflow-worker`
   - `noted-airflow-triggerer`
   - `noted-mlflow`
   - `noted-minio`
   - `noted-nginx` (only with local override)
5. Run `docker logs noted` and verify no startup errors (especially no `bash\r` CRLF errors)

## Test 2: Access noted

1. Open a browser and navigate to:
   - Domain setup: `https://yourdomain.com/noted`
   - Local setup: `http://localhost:6543`
   - Direct (no proxy): `http://localhost:8123`
2. **Expected:** noted loads with the Explorer panel on the left and a notebook area in the center
3. **Expected:** The Welcome notebook opens by default

## Test 3: Access MLflow from noted

1. In noted, click the MLflow icon in the bottom of the left icon bar
2. **Expected:** A new tab opens with the MLflow UI loaded in an iframe
3. **Expected:** MLflow shows "Experiments" page with at least the "Default" experiment
4. **Expected:** No browser console errors related to cross-origin or blocked frames

## Test 4: Access Airflow from noted

1. Click the Airflow icon in the icon bar
2. **Expected:** Airflow web UI loads in an iframe tab
3. **Expected:** Airflow login page appears (or dashboard if auto-logged in)
4. Log in with default credentials: `airflow` / `airflow`
5. **Expected:** Airflow dashboard shows with DAGs listed

## Test 5: Access MinIO from noted

1. Click the MinIO icon in the icon bar
2. **Expected:** MinIO console loads in an iframe tab
3. Log in with credentials from `.env`: `admin` / `password` (defaults)
4. **Expected:** MinIO dashboard shows with bucket management
5. Check that the `noted-dvc` bucket exists (or will be created on first DVC push)

## Test 6: Verify mount configuration

1. Check `data/NOTED.md` contains your mounts in the YAML frontmatter:
   ```yaml
   ---
   mounts:
   - name: noted-testing
     host_path: /path/to/noted-testing
   ---
   ```
2. Check `data/docker-compose.mounts.yml` was auto-generated with volume entries for both `noted` and Airflow services
3. In the Explorer panel, expand the Mounts section in the workspace tree
4. **Expected:** The `noted-testing` project appears in the tree
5. Expand the mount
6. **Expected:** The contents of the mounted directory are visible (e.g., `data/`, `notebooks/`, `dags/`, `config/`)
7. **Expected:** Files are browsable and notebooks can be opened
8. If the mount has a `dags/` folder, check the Pipelines section in Explorer
9. **Expected:** DAGs from the mount's `dags/` folder appear in the Pipelines tree

## Test 7: Service status indicators

1. Check the service icons in the icon bar
2. **Expected:** Service icons are clickable and responsive
3. Open each service tab, then close it
4. **Expected:** Tab indicators update correctly (active/inactive state)

## Test 8: Network connectivity between services

1. Open a notebook and start a kernel (any venv)
2. Run: `import mlflow; print(mlflow.get_tracking_uri())`
3. **Expected:** Output shows `http://mlflow:5000` (internal Docker networking)
4. Run: `mlflow.search_experiments()`
5. **Expected:** Returns at least the Default experiment (confirms noted can reach MLflow)

## Troubleshooting

- **Container crashes immediately:** Check `docker logs <container-name>` for errors
- **`bash\r` error in noted logs:** CRLF issue - run `git add --renormalize .` and `git checkout -- scripts/ services/run.sh`
- **Services unreachable from iframes:** Ensure you're accessing noted through the nginx proxy (port 6543 or domain), not directly on port 8123
- **MinIO login fails:** Check `MINIO_ROOT_USER` and `MINIO_ROOT_PASSWORD` in `.env`
- **Airflow login fails:** Default credentials are `airflow`/`airflow` (set via `_AIRFLOW_WWW_USER_USERNAME`/`_AIRFLOW_WWW_USER_PASSWORD` in `.env`)
- **Mount not visible:** Verify mount is listed in `data/NOTED.md` frontmatter and `data/docker-compose.mounts.yml` includes the volume entry. Restart with the mounts file included in the compose command.
- **DAGs not visible in Pipelines:** Ensure the mount's `dags/` folder is mounted to Airflow services in `docker-compose.mounts.yml`. Restart Airflow services.
- **Full reset (clears Postgres, MLflow, MinIO data):** `docker compose -f docker-compose.yml -f docker-compose.gpu.yml -f ../data/docker-compose.mounts.yml down -v` then rebuild
